
### #1: Agent action explainability panel

**Core idea:** given an "agent action" (like "drafted a follow-up to Sarah"), reconstruct and display exactly which records/fields/messages the agent reasoned from to produce it.

**Data model (mock, no real integrations needed):**

- `contacts` — name, company, email, last_contacted
- `deals` — id, contact_id, stage, notes[], last_activity_date
- `emails` — thread with a contact, snippets
- `agent_actions` — id, type (e.g. "follow_up_drafted"), output_text, **source_refs[]** (this is the key field — a list of which contacts/deals/emails/notes it pulled from)

**How you actually build the "explainability" part** — two honest options:

- **Cheap/fast version:** you hardcode `source_refs` when generating the mock action (i.e., you decide upfront "this draft used deal #4, note #2, email #7"). This is totally fine for a demo — you're proving the _UI/UX and trust concept_, not solving attribution from scratch.
- **More impressive version:** actually call an LLM (Claude API) to generate the follow-up draft, and in the same prompt, ask it to return which input records it used, structured as JSON. Then you're demoing a real, working trace, not a mock.

**UI:** click an action in a feed → side panel opens → shows "sourced from: Deal #4 (Globex, stalled 9 days), Email thread with Sarah (July 2), Note: 'champion going on leave'" — basically a "show your work" view.

**Stack:** simplest is a single React artifact — mock data as JS objects, LLM call via API if you want the impressive version, no backend needed for a demo.
